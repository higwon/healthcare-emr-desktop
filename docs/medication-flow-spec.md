## 사용자와 첫 완성 흐름

본인이 등록한 약·영양제의 일정을 확인하고 복용 여부를 기록하는 개인 사용자.
직접 등록 또는 합성 카탈로그 검색 → 복용 일정 설정 → 등록 확인 → 오늘의 일정 → 복용 체크 → 날짜별 기록 확인.
임의의 복용량·횟수 추천 없이 사용자가 가진 일정만 입력한다. 치료 중단 권고와 앱의 일정 관리 종료를 구분한다.

## 화면 명세

| ID | 화면 | 주요 구성·행동 |
| --- | --- | --- |
| HC-01 | 오늘의 건강 | 오늘의 복약 요약, 체성분 연동 상태·최근 측정, 증상 기록 진입. 카드에서 관련 상세로 이동 |
| MED-01 | 복약관리 | 날짜 이동, 오늘로 이동, 예정 시간별 목록, 완료 수, 약 추가. 날짜별 일정 없음과 등록 약 없음 구분 |
| MED-02 | 약 등록 | 검색/직접 등록 선택. 이름·종류, 검색 결과 선택; 직접 등록에는 검증된 약 정보가 없음을 표시 |
| MED-03 | 일정 설정 | 시작일, 종료일 선택, 매일/선택 요일, 복용 시각 추가·제거, 사용자 메모, 알림 설정 |
| MED-04 | 등록 확인 | 이름·일정·알림 요약 후 저장. 저장 중 중복 방지, 성공 후 생성된 카드로 이동 |
| MED-05 | 약 상세 | 등록 정보·일정·기록. 합성 카탈로그 설명과 개인 메모 구분. 알림 상태·일정 관리 종료 |
| MED-06 | 기록 조회 | 날짜별 체크 여부·기록 시각 조회. 첫 버전은 MED-01 날짜 탐색에서 제공 |

Windows 배치 제안: 왼쪽 제품 탐색, 가운데 날짜별 복약 목록, 오른쪽 선택 약 상세.
등록은 별도 단계형 패널로 열고 작성 초안 유지·닫기 동작을 명확히 한다. 작은 창에서는 상세를 별도 화면으로 전환한다.
시각 토큰·최소 창 크기는 시안 검토 후 확정한다. 고정 숫자와 색상을 지금 구현 계약으로 정하지 않는다.

## 자체 일정·기록 정책

- 첫 버전: 매일 또는 선택 요일, 하루 복수 시각, 시작·선택적 종료일. 필요시 복용·복잡한 주기·자동 용량 계산은 후속.
- 일정 시간대는 Asia/Seoul로 고정해 화면에 표시한다. 저장 시각은 UTC, 일정 날짜·시간은 시간대와 함께 저장한다.
- 복용 예정 항목은 계획 ID·일정 버전·날짜·시각으로 식별한다. 완료는 사용자 체크 기록이며 실제 복용 확인을 보증하지 않는다.
- 지난 예정 시각의 미체크는 '미기록'으로 표시한다. 자동으로 미복용·복용 완료 판정하지 않는다.
- 오늘 또는 과거 항목 체크·취소를 허용하고 미래 날짜 체크는 막는다. 체크 시각은 기록 시각으로 표현한다.
- 일정 수정은 다음 날부터 적용하며 이미 생성된 오늘·과거 항목을 유지한다. 적용일을 저장 전에 보여준다.
- 일정 관리 종료는 현재 시점부터 새 체크·알림을 막고 기존 기록을 유지한다. 재시작은 새 계획으로 등록한다.
- 알림 설정을 꺼도 일정·기록은 유지한다. 종료와 알림 끄기는 별도 행동이다.

## 상태와 복구

| 상태 | 화면·복구 |
| --- | --- |
| 등록 약 없음 | 약 추가 행동, 예시 데이터 자동 혼입 금지 |
| 해당 날짜 일정 없음 | 날짜 변경 또는 일정 확인. 등록 약 없음과 다른 문구 |
| 조회 중/실패 | 로딩·재시도; 지난 응답이 새 날짜 화면을 덮지 않음 |
| 저장 중 | 해당 항목 입력 방지. 완료 여부는 서버 응답 확인 후 변경 |
| 저장 실패 | 입력·체크 전 상태 유지, 원인 요약과 재시도 |
| 응답 유실 | 처리 확인 중 표시, 같은 작업 ID로 상태 확인 또는 재시도. 중복 기록 방지 |
| 오프라인 | 읽기 캐시와 조회 시각 표시; 첫 버전 쓰기 불가, 온라인 복귀 시 재조회 |
| 동시 수정 | 서버 버전 충돌 안내, 최신 데이터 확인 후 다시 선택 |
| 종료된 계획 | 종료 시각·기존 기록 표시, 체크·알림 사용 불가 |
| 알림 사용 불가 | 설정과 실제 전달 상태 구분. Windows 구현 방식 확정 전 전달 보장 문구 없음 |

## 최소 모델과 기술 경계

MedicationEntry: 이름·약/영양제 종류·직접입력/카탈로그 출처·선택적 카탈로그 ID·메모.
MedicationPlan: 등록 항목·시작/종료일·요일·시각·시간대·알림 설정·버전·관리 종료 시각.
DoseOccurrence: 계획·일정 버전·예정 날짜/시각·체크 기록 참조.
IntakeRecord: 예정 항목·체크/취소 상태·기록 시각·서버 버전.
최소 작업 결과 저장: 서버 adapter의 기술 책임. 최신 범위는 domain-rules/api-contracts를 따르며 공통 Domain entity로 만들지 않는다.

MVVM은 화면 상태·명령을 맡고 일정 계산·날짜 경계는 독립 로직으로 둔다.
조회 취소와 최신 요청 확인을 함께 사용한다. 실제 API 대신 합성 데이터 서버로 저장·실패·지연·충돌을 검증한다.
OCR·네이버 로그인·인바디·실제 약 검색·의학적 설명 생성은 첫 수직 구현에서 제외한다.
Windows 알림은 구현 방식·앱 종료/절전 동작 검증 후 별도 작업으로 연결한다.
