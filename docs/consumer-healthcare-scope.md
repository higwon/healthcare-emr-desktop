# 소비자 헬스케어 기능 기준

> 2026-09-30 방향 보정: 이 문서는 공개 서비스 조사 또는 기존 Medication 시안 참고자료다.
> 현재 제품 요구·구현 순서는 [제품 범위](project-overview.md)와 [Epic/Task](epics-and-tasks.md)를 따른다.
> 소비자 앱 재현과 Medication 우선 구현을 현재 기준으로 해석하지 않는다.

정정일: 2026-09-30. 사용자 제공 healthcare.naver.com 화면과 공식 도움말을 기준으로 한다.
구현 우선순위는 포트폴리오 설계 제안이며 실제 네이버 Windows 제품의 기능표나 API 계약을 의미하지 않는다.

## 확인된 기능과 설계 후보

| 기능 | 확인 근거 | 설계 후보 |
| --- | --- | --- |
| 바디리포트·바디 브리핑 | 홈 및 공식 FAQ: 날짜별 체중·골격근량·체지방률·체지방량, 코너별 AI 해석 | 연동 상태, 측정 목록·추이·결측 처리. 로그인 후 실제 내부 화면은 미확인 |
| 복약관리 | 화면 및 공식 도움말: 약·영양제 등록, 시간 알림, 복용 여부 기록, 약 정보 | 복약 상태 변경 Feature의 참고 흐름; 첫 구현은 데이터 탐색 |
| 증상체크 | 홈 및 공식 사용방법: 주요 증상 → 성별·연령 → 추가 질문 → 질병·의료기관 정보 | 질문·기록 UI. 구체적 질문·분기·판정·내부 결과 화면은 미확인 |
| 만보기 | 오늘의 걸음과 네이버앱 시작 안내 | 합성 걸음 데이터 조회. PC 측정이나 실제 앱 데이터 수신을 주장하지 않음 |
| 병원 예약 | 다가오는 예약과 병원 예약하기 | 예약 요약·외부 연결 후보. 진료·처방·청구로 확대하지 않음 |
| 생활·보건 지수 | 지역별 지수 카드 | 보조 정보 후보. 출처·이용 조건 확인 전 실제 연동 미확정 |
| 건강미션 | COMING SOON 표시 | 초기 구현 범위에서 제외 |
| 건강 클립·건강판·보험금 신청 | 콘텐츠·외부 연결 카드 | 첫 구현 이후 검토 |

첫 화면 후보는 오늘의 건강 홈이다. 복약, 최근 체성분 기록·연동 상태, 증상 기록 진입을 우선 배치한다.
화면의 카드 구조·정보 위계·상태 표현을 참고하고 Windows 탐색·키보드·크기 변경은 자체 설계한다.
제공된 화면은 홈 두 장이다. 내부 화면 확인 전 상세 UI를 실서비스 재현이라고 표현하지 않는다.

## 제품 및 기술 품질

- 로딩·빈 데이터·통신 실패·연동 해제·마지막 동기화 시각을 구분한다.
- 복용 기록의 저장 실패·재시도·취소·중복 입력·날짜 경계를 설계한다. Windows 알림 방식은 별도 결정한다.
- 체성분 그래프는 값·단위·측정 시각·출처와 결측을 표시한다. AI 분석 안내만으로 자체 건강 판정 알고리즘을 가정하지 않는다.
- 증상 결과·약 정보는 검증된 데이터 계약이 필요하다. 시연에서는 합성 데이터를 표시하며 의료 판단을 임의 생성하지 않는다.
- WPF MVVM, 비동기 취소, 응답 순서 역전 방지, 가상화, 그래프 Custom Control, DPI·접근성·설치를 검증한다.
- 네이버 로그인·인바디 연동·푸시·의약품 검색 API의 접근 권한과 계약은 확인되지 않았다. 실제 연동과 시뮬레이터를 구분한다.

## 직무와의 관계

지원 직무는 EMR Windows Client 개발이다. 소비자 건강관리 앱은 건강 데이터 UI와 WPF 엔지니어링 역량을 보여주지만 병원 EMR 업무 경험을 직접 증명하는 범위는 제한된다.
프로젝트는 '네이버 소비자 헬스케어 기능을 참고한 자체 Windows 앱'으로 설명한다. 채용 대상 제품을 구현했다고 주장하지 않는다.
기록함·가족 공유·병원 전달 및 진료 워크스페이스 시안은 보류한다. 기술 버전·아키텍처는 이 범위로 다시 검토한다.
