# 오늘의 건강·복약관리 UI 시안 검토

2026-09-30. 소스: [UI fragment](../design/prototypes/health-daily.html).
가칭 '건강노트'의 자체 Windows 화면 시안이다. 네이버 로고·제품명이나 실제 연동을 사용하지 않는다.
WPF 구현 이전에 정보 구조·입력 흐름·상태를 검토하기 위한 로컬 프로토타입이다.

## 화면 결정

- 좌측 탐색: 오늘의 건강, 복약관리, 바디리포트, 증상기록.
- 홈: 오늘의 복약을 중심으로 완료 상태와 남은 일정을 표시한다. 체성분 연결과 증상기록은 보조 카드로 배치한다.
- 복약관리: 날짜별 일정 목록과 선택 약 상세를 두 열로 배치한다. 좁은 화면에서는 상세를 아래에 배치한다.
- 약 등록: 이름·종류 → 시작/종료일·시각·메모·알림 → 요약 확인의 세 단계.
- 약 상세: 일정, 기간, 알림, 등록 방식, 사용자 메모와 일정 관리 종료.
- 색상: 녹색은 주 행동·선택·완료, 붉은 계열은 오류에 사용하며 문구로 상태를 함께 설명한다.
- 기본 글자 14px, 제목 27px, 카드 간격 16px, 모서리 16px의 시안 토큰. WPF에서는 DPI에 대응하는 DIP와 리소스 토큰으로 옮긴다.
- 밝은/어두운 모드 색상을 정의했다. 이번 브라우저 시각 검토는 밝은 모드로 수행했다.

## 실제로 확인한 동작

| 검증 | 결과 |
| --- | --- |
| 홈·복약관리 전환 | 주요 정보와 탐색 선택 표시 확인 |
| 직접 등록 | 이름·시각·메모 입력 → 확인 → 목록·상세 생성 확인 |
| 복용 체크·취소 | 상태와 완료 표시 변경 확인 |
| 저장 실패 | 기존 체크 상태 유지·실패 안내 확인 |
| 체크 재시도 | 재시도 성공 후 상태 변경 확인 |
| 등록 실패·재시도 | 확인 단계 초안 유지·연결 복구 후 등록 확인 |
| 일정 종료 확인 | 확인 화면·종료 처리 실행. 상세 정책은 WPF 테스트에서 별도 검증 필요 |
| 종료일 검증 | 시작일보다 이른 종료일을 막는 문구 확인 |
| 빈 상태 | 등록 없음, 해당 날짜 일정 없음의 UI 분리 |
| 키보드 | 모달 처음에서 Shift+Tab 시 마지막 버튼으로 순환, Escape 닫기와 약 추가 버튼 포커스 복귀 확인 |
| 폭 변경 | 1024·360·320px 확인. 탐색·상세 재배치와 좁은 폭의 가로 넘침 점검 |

등록 단계 전환 문제를 브라우저에서 발견해 명시적 단계 버튼으로 수정했다.
저장 실패 복구 행동, 일정 기간·알림 설정 표시, 모달 배경 입력 차단과 초점 복귀를 보완했다.

## 이번 시안의 제한

- 합성 데이터와 로컬 상태만 사용한다. 서버 저장·실제 알림·의약품 API·OCR·인바디 인증은 없다.
- 매일 한 시각의 일정 입력만 조작한다. 선택 요일·복수 시각은 명세에는 있지만 시안에서 아직 구현하지 않았다.
- 오늘 이외 날짜는 일정 없음 상태를 검토한다. 과거 날짜별 복용 상태 저장은 구현하지 않았다.
- 등록 시작/종료일은 보존하고 오늘 일정 포함 여부에 반영한다. 미래 일정 조회·일정 수정·다음 날 적용은 후속이다.
- 화면 하단 상태 검토 버튼은 시안 검토 도구이며 실제 제품 화면에 들어가지 않는다. 정상/빈/오류 전환 시 예시 데이터를 초기화한다.
- 바디리포트는 연결 상태와 합성 수치 요약만 제공한다. 날짜별 추이·AI 패널·증상 질문은 후속 시안 범위다.
- Windows DPI, UI Automation, 실제 배포·성능은 아직 검증하지 않았다.

## 다음 구현 준비

이 시안을 기준으로 탐색·카드·목록·상세·등록 단계·오류 메시지를 WPF 리소스와 ViewModel 상태로 매핑한다.
기술 버전 ADR과 최소 솔루션을 먼저 만들고, 직접 등록 → API 저장 → 일정 조회 → 복용 기록을 첫 수직 구현으로 진행한다.
